# Полная теория проекта «User Registration»

Объяснение для читателя, который только начинает знакомиться с программированием. В тексте названы конкретные функции, свойства и методы, которыми выполняется каждое действие, и пояснено, почему выбран именно этот способ.

## 1. Что получилось

Проект — это небольшая веб-страница, на которой можно зарегистрировать человека по имени и возрасту. Если данные подходят правилам, программа добавляет человека в список без перезагрузки страницы. Если данные неверны, программа показывает причину на самой странице и записывает её в Console браузера.

Реализована обязательная часть задания: функция `createUser`, проверка данных, генерация `id`, хранение пользователей через замыкание в `createUserManager`, обработка формы и ошибок, отображение списка методами DOM, сообщения Console и очистка полей после успеха. Выполнены все дополнительные части:

- **A — счётчик.** Рядом с заголовком списка показывается общее количество записей.
- **B — удаление.** У каждой записи есть кнопка `Delete`.
- **C — фильтр.** `Show All` показывает всех, а `Show Adults` — пользователей от 18 лет.

Вёрстка сделана в спокойном деловом стиле. Данные хранятся только в памяти JavaScript. Поэтому обновление страницы начинает новый список — сервер, база данных и `localStorage` не используются, как и требует задание.

## 2. Какие файлы входят в проект

| Файл | Роль |
| --- | --- |
| `index.html` | Описывает содержимое страницы: заголовки, поля, кнопки, счётчик, список и место для сообщений. |
| `css/main.css` | Описывает общую палитру, ширину страницы, карточки, заголовки, отступы и адаптацию общего макета. |
| `css/form.css` | Описывает поля, кнопки, сообщения, фильтры и строки пользователей. |
| `js/user.js` | Создаёт проверенного пользователя и выдаёт ему уникальный `id`. |
| `js/userManager.js` | Хранит записи в локальном массиве, который закрыт замыканием, и предоставляет методы управления им. |
| `js/app.js` | Связывает данные с HTML: обрабатывает форму и кнопки, меняет список, счётчик и сообщения. |
| `README.md` | Даёт короткие инструкции запуска и перечисляет возможности. |
| `THEORY_RU.md` | Даёт полное объяснение работы проекта. |

У каждого JavaScript-файла своя задача. `user.js` проверяет данные, не обращаясь к странице. `userManager.js` управляет коллекцией, не создавая HTML. `app.js` связывает логику с DOM. Такое разделение позволяет менять, например, вид страницы, не переписывая правила проверки возраста.

## 3. Путь данных: что происходит при нажатии Register

1. Браузер замечает отправку формы и вызывает `handleRegistration`, добавленную методом `addEventListener("submit", ...)`.
2. `event.preventDefault()` отменяет обычную отправку формы, которая перезагрузила бы страницу.
3. Свойство `.value` объектов `nameInput` и `ageInput` возвращает введённые данные. Значение поля браузер передаёт как текст.
4. Проверка `rawAge.trim() === ""` выявляет пустой или состоящий из пробелов возраст. Пустоте назначается `null`. Иначе функция `Number(rawAge)` преобразует строку в число.
5. Функция `createUser({ name: rawName, age })` получает один объект со значениями и проверяет правила. При проблеме она останавливается через `throw new Error(...)`; при успехе возвращает новый объект с `id`, очищенным именем, числовым возрастом и дополнительными полями.
6. Метод `userManager.addUser(user)` помещает готовый объект в закрытый массив.
7. Функция `renderUsers()` вызывает `userManager.getUsers()`, получает копию массива и строит DOM-элементы списка заново.
8. В `catch` ошибка показывается через `console.error()` и `showMessage()`. В `finally` для любой попытки печатается `Registration attempt completed`.

Порядок важен: вызов `addUser` расположен после `createUser`. Если проверка выбросит ошибку, JavaScript сразу перейдёт к `catch`, поэтому некорректный объект не попадёт в хранилище. Ранее зарегистрированные записи при этом не затрагиваются.

## 4. HTML: из чего состоит страница и как её находит JavaScript

HTML можно представить как план комнаты: он задаёт, какие предметы в ней есть. CSS описывает внешний вид этих предметов, а JavaScript задаёт их поведение.

В `index.html` есть семантические области `<main>`, `<header>`, `<section>` и `<footer>`. Это элементы HTML, смысл которых понятен и браузеру, и вспомогательным технологиям. Форма `<form>` содержит подписи `<label>`, текстовое поле имени, числовое поле возраста и кнопку отправки. Список начинается с `<ul>`, а отдельная строка списка имеет тег `<li>`.

Для каждого узла, которым управляет JavaScript, в разметке установлен уникальный `id`, например `registration-form` или `user-list`. В `app.js` выражение `document.querySelector("#user-list")` находит элемент с таким `id`. Знак `#` означает «найти элемент по CSS-селектору id». Полученную ссылку сохраняет `const userList`, поэтому повторный поиск для каждой операции не нужен.

Поле имени имеет `type="text"`, потому что имя — текст. Возраст имеет `type="number"`, чтобы браузер показал подходящий для чисел ввод. Но браузерное поле всё равно отдаёт значение через `.value` как строку, поэтому JavaScript преобразует её через `Number`.

У формы установлен `novalidate`: браузер не останавливает отправку своей встроенной проверкой до запуска нашего обработчика. Это позволяет всегда показать единое сообщение из программы и выполнять `finally` при каждой попытке. Правила возраста и обязательности данных реализованы в `createUser`, где их можно прочитать и объяснить.

Кнопка `Register` имеет `type="submit"`, а кнопки фильтра и удаления — `type="button"`. Это различие не даёт `Delete` или фильтру случайно отправить форму.

Три JavaScript-файла подключены внизу `<head>` с атрибутом `defer`. Браузер загружает их, сначала разбирает HTML, а потом запускает скрипты по порядку. Поэтому `app.js` успевает найти готовые HTML-элементы и использует функции из предыдущих файлов. `type="module"`, `import` и `export` здесь не нужны и запрещены условиями задания.

## 5. CSS: визуальная концепция и выбор оформления

Концепция — **спокойный деловой интерфейс**: светлый серо-зелёный фон, белые рабочие поверхности, тёмный мягкий текст и один основной хвойный акцент. Кирпичный цвет применяется только для ошибок и удаления, зелёный — для подтверждений. Это помогает быстро различать состояния и не перегружает страницу яркими цветами.

Палитра записана в `:root` в виде CSS-переменных, например `--page`, `--surface`, `--ink` и `--accent`. В остальных правилах цвет задаётся через `var(--accent)`. Так проще менять цветовую тему: достаточно исправить переменную в одном месте. Альтернатива — копировать шестнадцатеричные коды в каждое правило. Она работает, но повышает риск забыть обновить одно из повторяющихся значений.

Стили разделены на два файла по назначению: `main.css` отвечает за общую композицию и палитру, `form.css` — за элементы взаимодействия. CSS Grid (`display: grid`) делит широкую форму на равные поля имени и возраста и место кнопки; Flexbox (`display: flex`) выравнивает элементы в строках, например имя и Delete. Это встроенные средства CSS, поэтому проект не зависит от внешнего фреймворка.

Правило `@media (max-width: 640px)` переводит форму в одну колонку и распределяет фильтры в две равные кнопки, когда экран узкий. Ещё один `@media` уменьшает общие отступы при ширине до 560 пикселей. Запрос `prefers-reduced-motion` уважает системную настройку уменьшения движения. `:focus-visible` рисует кольцо вокруг элемента, выбранного клавиатурой. Эти правила помогают пользоваться приложением не только мышью и на широком экране.

Шрифты системные: `Segoe UI`, `Arial`, `Georgia`. Они доступны в типичных системах, поэтому браузер ничего не скачивает и проект запускается без интернета. CSS-фреймворк и внешние изображения не нужны: небольшой интерфейс можно выразить несколькими обычными правилами, сохранив прозрачность учебного кода.

## 6. Основы JavaScript, используемые в проекте

- **Переменная** хранит значение под именем. `const` используется, если ссылку не нужно переназначать; `let` — если переменная позже получит новое значение. Например, `currentFilter` меняется при переключении кнопок, а `users` получает новый массив после удаления. `const` не делает массив неизменяемым: `users.push(...)` всё ещё может добавить элемент.
- **Функция** — именованная последовательность действий. Значения, поступающие в функцию, называются параметрами внутри объявления и аргументами при вызове. `return` отдаёт результат вызывающему коду.
- **Объект** хранит связанные поля с названиями: `{ id: 1, name: "Anna", age: 28 }`.
- **Массив** хранит элементы по порядку: `[user1, user2]`.
- **Стрелочная функция**, например `() => handleDelete(id, name)`, создаёт короткую функцию для обработчика события.
- **Событие** — факт действия в браузере: отправка формы, щелчок по кнопке. **Обработчик** — функция, которую браузер вызывает для этого события.

`var` не используется: помимо запрета в задании, его правила области видимости сложнее для начинающего. `const` и `let` имеют более ясную блочную область видимости.

## 7. Как работает `createIdGenerator` и его замыкание

В `user.js` есть функция `createIdGenerator`. Вызов `createIdGenerator()` создаёт локальную переменную `lastId` со значением `0`, затем возвращает внутреннюю функцию `nextId`. В `nextUserId` сохраняется именно возвращённая функция.

Когда `nextUserId()` вызывается, функция делает `lastId += 1` и возвращает `lastId`. При первом вызове результат равен `1`, при следующем — `2`. Внешняя функция уже закончила выполняться, но внутренняя продолжает помнить `lastId`. Это и есть **замыкание**: функция сохранила доступ к переменным из области, где её создали.

Если бы `lastId` находилась в `createUser`, она каждый раз начиналась бы с нуля и номера повторялись бы. Если бы счётчик был глобальной переменной, любой скрипт на странице мог бы случайно его изменить. Замыкание одновременно сохраняет значение между вызовами и закрывает его от прямого вмешательства.

Функция создаётся один раз строкой `const nextUserId = createIdGenerator()`. Поэтому все вызовы `createUser` используют один последовательный счётчик. Перезагрузка страницы создаёт новый запуск, поэтому идентификаторы снова начинаются с 1. Уникальность обещана в рамках одного запуска, а не между перезагрузками или разными браузерами.

## 8. Объектный параметр, деструктуризация, Rest и Spread

`createUser` объявлена как `function createUser({ name, age, ...extraProps } = {})`. При вызове ей передают один объект: `createUser({ name: "Anna", age: 28 })`. Деструктуризация сразу извлекает свойства `name` и `age` в одноимённые локальные переменные.

Если бы функция принимала два отдельных аргумента, вызов выглядел бы как `createUser("Anna", 28)`. Объект выбран потому, что его поля подписаны: порядок легче читать, а дополнительные значения можно передавать, не придумывая всё новые позиции аргументов. Альтернативный способ — внутри функции вручную писать `const name = data.name`, `const age = data.age`; он даёт тот же результат, но занимает больше строк.

Три точки в `...extraProps` — **Rest-синтаксис**. Здесь он собирает в объект все остальные свойства входного объекта, кроме уже извлечённых `name` и `age`. Например, из `{ name: "Anna", age: 28, city: "Haifa" }` получится `extraProps = { city: "Haifa" }`.

Три точки в `...extraProps` при создании результата — **Spread-синтаксис**. Он копирует поля дополнительного объекта в новый объект пользователя. В менеджере выражение `[...users]` создаёт новый массив, элементы которого перечислены из старого массива.

В объекте пользователя собственные `id`, `name` и `age` идут после `...extraProps`. Если два свойства с одинаковым именем встретились при создании объекта, значение справа перезаписывает значение слева. Поэтому сгенерированный `id` и проверенные `name`/`age` не будут подменены дополнительным свойством с таким именем.

## 9. Как `createUser` проверяет имя и возраст

### Имя

1. `typeof name !== "string"` проверяет, что имя действительно строка.
2. `name.trim()` возвращает новую строку без пробелов в начале и конце. Саму исходную строку `trim()` не изменяет.
3. Если очищенная строка равна `""`, имя отсутствует или состоит из пробелов, и функция выполняет `throw new Error("Name is required")`.
4. Для правильного имени результат `trim()` сохраняется в `cleanName` и попадает в возвращаемый объект.

`trim()` выбран вместо ручного удаления символов, потому что это встроенный метод для удаления пробельных символов по краям. Он не обрезает пробелы внутри имени: `"Mary Jane"` остаётся `"Mary Jane"`.

### Возраст

`ageInput.value` приходит как строка, даже если в поле написаны цифры. В `handleRegistration` сначала проверяется `rawAge.trim() === ""`. Это нужно сделать **до** преобразования: в JavaScript `Number("")` равно `0`, а пустое поле не должно незаметно стать возрастом ноль. Пустоте присваивается `null`, чтобы `createUser` вернула отдельную ошибку `Age is required`.

Значение передаётся как число через `Number(rawAge)`. В `createUser` пустые `null`, `undefined` и пустая строка проверяются отдельно. Затем `typeof age` ограничивает поддерживаемые входы числами и строками: например, `Number(true)` равно `1`, поэтому логическое значение не следует принимать за возраст.

Поле `type="number"` в браузере может не принимать буквы или преобразовать некорректный ввод в пустое значение ещё до чтения `.value`. В таком браузере попытка ввести `abc` может быть распознана приложением как пустое поле и получить `Age is required`. Сама функция `createUser` всё равно проверяет произвольную строку: `Number("abc")` даёт `NaN`, после чего срабатывает `Invalid age`. Это различие зависит от поведения элемента ввода конкретного браузера.

`Number(age)` преобразует строку `"28"` в число `28`. Строка `"abc"` даст `NaN` (специальное значение «не число»). После преобразования `Number.isInteger(numericAge)` возвращает `true` только для целого числа. Этим выражением отклоняются `25.5`, `NaN` и бесконечность. Две остальные проверки требуют `numericAge >= 0` и `numericAge <= 120`, значит 0 и 120 допустимы.

Почему выбран `Number`, а не `parseInt`: `parseInt("25.5", 10)` вернёт `25`, хотя исходный ввод был дробным. `Number("25.5")` сохраняет дробную часть, а `Number.isInteger` правильно отклоняет значение. Проверки с `isNaN` могли бы отловить только нечисловое значение, но сами по себе не проверили бы целочисленность и границы.

### Собственная ошибка

`throw new Error("...")` создаёт стандартный объект ошибки с текстом в его свойстве `message` и прекращает текущий путь выполнения. Движок передаёт ошибку вверх по цепочке вызовов до ближайшего подходящего `catch`. Это лучше, чем возвращать специальные строки вроде `"ERROR"`, потому что успешное значение и сигнал об ошибке разделены явно, а `try...catch` умеет работать именно с исключениями.

## 10. Замыкание хранилища: `createUserManager`

`createUserManager()` создаёт локальный массив `users = []` и возвращает объект с методами `addUser`, `getUsers` и `removeUser`. Все три метода объявлены внутри фабрики и используют её `users`. После выхода из `createUserManager` массив не исчезает, потому что возвращённые функции его помнят. Это второе замыкание проекта.

В `app.js` переменная `userManager` содержит объект с разрешёнными операциями. Переменной `users` там нет: из `app.js` невозможно непосредственно вызвать `users.push`, потому что имя `users` локальное для `createUserManager`. Это называют **инкапсуляцией** — внутреннее состояние закрыто, а наружу открыты только заранее выбранные способы работы.

### `addUser(user)`

Метод принимает объект и вызывает `users.push(user)`. `push` добавляет элемент в конец массива и меняет сам массив. Вызов `push` выбран потому, что запись должна добавиться к текущей коллекции, а порядок регистрации нужно сохранить. Метод не обновляет HTML: он управляет только данными, а за DOM отвечает `app.js`.

### `getUsers()`

Метод возвращает `[...users]`. Spread создаёт новый массив-контейнер, поэтому вызывающий код не сможет напрямую добавить или удалить элементы во внутреннем массиве. Альтернатива — вернуть `users` напрямую, но тогда любая функция в `app.js` смогла бы очистить или изменить исходную коллекцию в обход менеджера.

Это **поверхностная копия**: сам массив новый, но объекты записей внутри него те же. Для задания этого достаточно, потому что интерфейс читает объекты и меняет коллекцию только методами менеджера. Если нужно полностью защитить вложенные объекты от изменения свойств, можно копировать каждую запись, например `users.map((user) => ({ ...user }))`. Это дополнительная мера, не требуемая текущей задачей.

### `removeUser(userId)`

Метод запоминает прежнее число записей в `originalLength`, а затем присваивает `users` результат `users.filter(({ id }) => id !== userId)`. `filter` проходит по старому массиву и создаёт новый из тех элементов, для которых условие вернуло `true`. Запись с нужным `id` не проходит, остальные сохраняются. Деструктуризация `{ id }` достаёт идентификатор каждого пользователя прямо в параметре стрелочной функции.

Здесь выбран `filter`, потому что по условию нужно получить массив без удаляемой записи и не требуется вычислять индекс. Альтернатива — `findIndex` и `splice`, где массив меняется на месте; тогда пришлось бы отдельно обрабатывать случай, когда индекс не найден. Так как `filter` возвращает новый массив, `users` объявлена через `let`, а не `const`.

Сравнение `users.length < originalLength` возвращает `true`, если запись удалена, и `false`, если такого `id` не было. `handleDelete` использует этот результат для выбора сообщения и типа записи в Console.

## 11. Как `app.js` связывает страницу и хранилище

### Поиск элементов

`document.querySelector("#..." )` находит первый узел, соответствующий CSS-селектору. Селектор с `#` указывает на `id`. Для примера, `document.querySelector("#age-input")` получает поле возраста. Ссылки хранятся в константах `nameInput`, `ageInput` и других.

Альтернатива — `document.getElementById("age-input")`, который тоже подходит для поиска по id. `querySelector` выбран потому, что он работает с привычным CSS-синтаксисом и может в будущем искать не только по `id`; оба метода являются штатными возможностями браузера.

### `showMessage(message, kind)`

Функция присваивает `formMessage.textContent = message`, то есть записывает обычный текст в область статуса. Затем `classList.toggle("is-error", kind === "error")` включает класс, если второй аргумент равен `true`, и убирает класс, если равен `false`. CSS по этому классу выбирает спокойный красный стиль ошибки или зелёное оформление успеха.

`textContent` выбран вместо `innerHTML`, чтобы строка считалась текстом, а не разметкой. Например, если имя содержит `<img ...>`, браузер отобразит символы, а не создаст HTML-элемент. Это защищает от случайной интерпретации пользовательских данных как разметки.

### `getVisibleUsers(allUsers)`

Если `currentFilter` равно `"adults"`, метод массива `filter` создаёт список, где у каждой записи `age >= ADULT_AGE`. В другом случае функция возвращает весь снимок `allUsers`. Возрастной порог равен 18 и хранится в константе `ADULT_AGE`, чтобы правило имело ясное имя и не дублировалось числом по коду.

`filter` не меняет массив, на котором его вызвали. Поэтому скрытые дети остаются во внутреннем хранилище и снова появляются при переключении на `Show All`.

### `renderUsers()` и обновление списка

1. `userManager.getUsers()` возвращает копию массива. Она сохраняется в `allUsers`.
2. `getVisibleUsers(allUsers)` вычисляет видимые записи согласно фильтру.
3. В `userCount.textContent` записывается `allUsers.length`, то есть общее число людей даже при фильтре.
4. `userList.replaceChildren()` удаляет прежние DOM-дочерние элементы. Поэтому карточки строятся заново и не дублируются.
5. Если видимых элементов нет, `document.createElement("li")` создаёт подсказку, а `append` помещает её в список.
6. Иначе `visibleUsers.forEach(...)` запускает функцию для каждого элемента массива. В её параметре `({ id, name, age })` деструктуризация получает три свойства пользователя.
7. `document.createElement(...)` создаёт узлы `li`, `div`, `span` и `button` по одному. `className` связывает их с CSS.
8. В `nameLabel.textContent` попадает имя. Возраст превращается в подпись шаблонной строкой, например `` `${age} years old` ``.
9. `details.append(nameLabel, ageLabel)` собирает текстовые элементы; `listItem.append(details, deleteButton)` собирает строку; `userList.append(listItem)` добавляет её на страницу.

`forEach` выбран, чтобы выполнить построение элементов для каждой записи; он не создаёт новый массив и не нужен для вычисления результата. Для преобразования массива в новый массив подойдовал бы `map`, а для поиска — `find`; здесь же нужна последовательная вставка DOM-узлов, поэтому `forEach` выражает задачу прямо. `replaceChildren` выбран для полной замены содержимого списка; альтернативой была бы ручная очистка циклами `removeChild`.

### Почему DOM строится через `createElement` и `textContent`

Пользовательское имя — внешнее содержимое. Код создаёт безопасные стандартные элементы функцией `document.createElement`, добавляет их через `append`, а текст записывает через `textContent`. Запрещённый в задании `innerHTML` здесь не используется. Если вставлять данные через `innerHTML`, браузер будет трактовать угловые скобки как разметку. При `textContent` они остаются текстом.

## 12. Регистрация и `try...catch...finally`

`registrationForm.addEventListener("submit", handleRegistration)` регистрирует обработчик отправки. Событие `submit` возникает и при щелчке по `Register`, и при отправке клавишей Enter из поля. Можно было подписаться на `click` самой кнопки, но тогда поддержка Enter потребовала бы дополнительной логики. Обработчик формы проще и соответствует поведению HTML-формы.

В начале `handleRegistration(event)` вызывается `event.preventDefault()`. Это метод объекта события, который отменяет стандартную перезагрузку документа. Далее выполняются действия регистрации внутри `try`:

| Действие | Каким выражением или методом | Зачем |
| --- | --- | --- |
| Прочитать имя | `nameInput.value` | Свойство `value` содержит текущий введённый текст. |
| Прочитать возраст | `ageInput.value` | Браузер предоставляет содержимое числового поля как строку. |
| Отличить пустое от нуля | `rawAge.trim() === "" ? null : ...` | `Number("")` дало бы 0, поэтому пустоту выявляем заранее. |
| Преобразовать возраст | `Number(rawAge)` | Возвращает число, с которым можно проверять диапазон. |
| Передать имя и возраст | `createUser({ name: rawName, age })` | Один объект с подписями полей легче прочитать и расширить. |
| Сохранить пользователя | `userManager.addUser(user)` | Только метод менеджера меняет закрытый массив. |
| Обновить интерфейс | `renderUsers()` | Функция перечитывает актуальные данные и создаёт DOM-строки. |
| Очистить форму | `registrationForm.reset()` | Стандартный метод формы возвращает элементы к начальному состоянию. |
| Продолжить ввод | `nameInput.focus()` | Метод `focus()` возвращает курсор в первое поле. |

`catch (error)` получает объект ошибки, выброшенный `createUser`. Деструктуризация `const { message } = error` достаёт его текст. `console.error(message)` выводит ошибку в инструменты разработчика, а `showMessage(message, "error")` — в область статуса на странице.

`finally` выполняется после `try` и `catch`, поэтому `console.log("Registration attempt completed")` появляется как при успехе, так и при ошибке. Без `finally` пришлось бы повторять одинаковый вызов Console в двух ветках. В успешном случае выполняется `registrationForm.reset()`, а при ошибке поля сохраняются, чтобы человек мог исправить ввод.

## 13. Дополнительные части A, B и C

### A — общее количество пользователей

В `renderUsers` число `allUsers.length` записывается в `userCount.textContent`. Это количество всех записей, полученное через `getUsers`, до применения фильтра. При добавлении и удалении вызывается `renderUsers`, поэтому счётчик автоматически пересчитывается. Переключение фильтра тоже вызывает отрисовку, но число остаётся общим и не уменьшается из-за скрытых детей.

### B — удаление пользователя

Для каждой строки `renderUsers` создаёт кнопку Delete и назначает ей обработчик методом `deleteButton.addEventListener("click", ...)`. Стрелочная функция `() => handleDelete(id, name)` замыкает конкретные `id` и `name` текущего прохода `forEach`. Через некоторое время, когда пользователь нажмёт эту кнопку, функция всё ещё знает, какую запись удалить.

`handleDelete` передаёт `id` в `userManager.removeUser`. После этого вызывает `renderUsers`, чтобы обновить строки и общий счётчик, а затем `showMessage`, чтобы показать результат. Обработчик и DOM остаются в `app.js`; само удаление внутреннего массива находится в `userManager.js`.

### C — фильтр совершеннолетних

Кнопка `Show Adults` вызывает `setFilter("adults")`, а `Show All` — `setFilter("all")`. `setFilter` меняет `currentFilter`, устанавливает атрибуты `aria-pressed` на кнопках, запускает `renderUsers` и записывает выбранный режим в Console.

При режиме взрослых `getVisibleUsers` применяет `filter(({ age }) => age >= 18)`. `filter` возвращает отдельный массив; внутренний список менеджера не переписывается. Если список пуст или нет взрослых, `renderUsers` показывает соответствующий текст, а счётчик всё равно отражает общее число зарегистрированных.

## 15. Доступность и безопасность

Подписи `<label for="name-input">` и `<label for="age-input">` связаны со своими полями через одинаковые значения `for` и `id`. Нажатие на подпись переводит курсор в поле; программы чтения экрана узнают название ввода. `aria-live="polite"` сообщает вспомогательным технологиям об изменениях сообщений и списка без резкого прерывания текущего чтения. У кнопок фильтра есть `aria-pressed`, у каждой кнопки Delete есть точная подпись `aria-label`, например `Delete Anna`.

Фокус клавиатуры видим благодаря `:focus-visible`. CSS-медиазапрос адаптирует расположение полей и фильтров для узкого окна. В CSS пользовательские данные никогда не читаются; в JavaScript они вставляются через `textContent`, а не `innerHTML`. Это снижает риск того, что введённые угловые скобки браузер воспримет как активную разметку.

## 16. Как запустить и где хранятся данные

Откройте `index.html` в современном браузере. HTML, CSS и JavaScript — единственные технологии проекта; устанавливать Node.js, npm, библиотеки или запускать сервер для обычного использования не нужно.

При загрузке `app.js` вызывает `createUserManager()`, который создаёт новый пустой массив в памяти JavaScript. После закрытия или обновления страницы этот массив перестаёт существовать. Это сознательный выбор по заданию. Для сохранения между запусками можно было бы использовать `localStorage`, а для нескольких людей и устройств — сервер и базу данных, но оба варианта меняют требования и архитектуру этой учебной работы.

## 19. Одной фразой для защиты

«Я передаю данные формы объектом в `createUser`, проверяю их и создаю запись с уникальным id; `createUserManager` хранит записи в замыкании и выдаёт только методы добавления, чтения и удаления, а `app.js` с помощью DOM строит список, считает записи, фильтрует взрослых и обрабатывает ошибки через `try...catch...finally`.»
