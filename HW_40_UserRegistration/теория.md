# Теория к проекту «User Registration»

Домашнее задание № 32 · объяснение 

## 1. Что мы сделали, простыми словами

Мы сделали маленький сайт — журнал регистрации. На странице два поля (имя и возраст) и кнопка Register. Нажимаем кнопку — программа проверяет введённое и делает одно из двух: добавляет человека в список или показывает понятное сообщение об ошибке. Список обновляется сразу, страница не перезагружается.

Представьте стойку регистрации в приёмной. Администратор смотрит на анкету: имя не пустое? возраст — целое число от 0 до 120? Если всё в порядке, он записывает человека в журнал и выдаёт ему личный номер. Если нет — вежливо объясняет, что исправить. Журнал лежит в ящике, к которому у посетителей нет доступа: записать и посмотреть можно только через администратора. Такой «ящик» в программировании называется замыканием — ему посвящён раздел 8.

Данные живут только в памяти браузера: обновили страницу — список очистился. Так и требовало задание: никаких серверов, баз данных и `localStorage`.

Дополнительно выполнены три необязательных задания: **A** — счётчик пользователей, **B** — кнопка Delete, **C** — фильтр Show All / Show Adults.

## 2. Из чего состоит проект

Любая страница в интернете строится из трёх слоёв:

- **HTML** — скелет: какие элементы есть на странице (заголовок, поля, кнопка, список).
- **CSS** — внешний вид: цвета, шрифты, отступы.
- **JavaScript** — поведение: что происходит, когда человек нажимает кнопку.

| Файл | За что отвечает |
| --- | --- |
| `index.html` | скелет страницы: заголовок, форма, область сообщений, список, фильтры |
| `css/main.css` | общие стили: цвета, шрифты, ширина центральной колонки |
| `css/form.css` | вид формы, кнопок, сообщений и списка |
| `js/user.js` | функция `createUser` (проверка данных, создание пользователя) и генератор номеров |
| `js/userManager.js` | функция `createUserManager` — «журнал» пользователей на замыкании |
| `js/app.js` | связь со страницей: нажатия кнопок, вывод на экран, сообщения |

**Почему JavaScript разделён на три файла.** У каждого файла одна задача. `user.js` ничего не знает о странице, `userManager.js` — тоже; только `app.js` «разговаривает» со страницей. Такой код легче читать, проверять и менять: например, заменить журнал на базу данных можно, не трогая проверку данных.

**Порядок подключения.** В `index.html` три скрипта подключены с атрибутом `defer`. Он означает: «скачай файл сразу, но выполни его, когда вся страница уже разобрана, и выполняй файлы строго в том порядке, в котором они написаны». Порядок важен: `app.js` использует функции из первых двух файлов, поэтому стоит последним. Режим `type=module` не используется (задание это запрещает), поэтому файлы видят друг друга через общую область страницы.

## 3. Как проходит регистрация: шаг за шагом

Когда человек нажимает Register, запускается функция `handleRegister` из `app.js`:

1. Берём значения из поля имени и поля возраста.
2. Проверяем, не пусто ли поле возраста. Пустое поле превращаем в особое значение `null` («ничего»). Почему не в ноль — см. раздел 7.
3. Превращаем текст возраста в число (`Number`).
4. Передаём имя и возраст в `createUser`.
5. `createUser` проверяет данные. Если что-то не так — выбрасывает ошибку, и программа сразу прыгает в блок `catch`; остальные шаги не выполняются. Если всё хорошо — возвращает объект пользователя с номером `id`.
6. Передаём объект в `addUser` — человек попадает в журнал.
7. Просим у журнала актуальный список (`getUsers`).
8. Обновляем список на странице.
9. Пишем в консоль браузера (открывается клавишей F12) сообщение об успехе.
10. Очищаем поля и показываем зелёное подтверждение.

В любом случае — и при успехе, и при ошибке — в консоль выводится `Registration attempt completed`. За это отвечает блок `finally`.

## 4. Базовые понятия

- **Переменная** — подписанная коробка для значения. `const` — коробка, на которую нельзя «повесить» другое значение. `let` — коробку можно заменить новым значением. Мы по умолчанию берём `const`, а `let` — только там, где значение действительно меняется: счётчик `lastId`, массив `users` после удаления, режим фильтра `currentFilter`. Слово `var` не используем: у него запутанные правила видимости, современный код его избегает (и задание его запрещает). Важная тонкость: `const` запрещает заменить массив целиком, но не мешает добавлять в него элементы.
- **Функция** — именованная инструкция «сделай вот это». Принимает аргументы (входные данные) и может вернуть результат через `return`.
- **Объект** — карточка с подписанными полями: `{ id: 1, name: 'Anna', age: 28 }`.
- **Массив** — нумерованный список значений: `[пользователь1, пользователь2]`.
- **Стрелочная функция** — короткая запись функции: `(user) => user.id !== userId` читается как «получив user, вернуть результат сравнения».
- **Событие и обработчик** — правило «когда случится X, вызови функцию Y». Его задаёт `addEventListener`.

## 5. Передача объекта и деструктуризация

Вместо `createUser('Anna', 28, 'Tel Aviv')` мы передаём один объект: `createUser({ name: 'Anna', age: 28 })`. Так порядок значений не важен, у каждого значения есть подпись, а новые поля можно добавлять, не ломая старые вызовы.

**Деструктуризация** — «распаковка» объекта в отдельные переменные. Без неё пришлось бы писать `const name = data.name; const age = data.age;`. С ней достаточно `function createUser({ name, age })` — JavaScript сам создаёт переменные `name` и `age` из одноимённых полей объекта.

Где это применено в проекте:

- параметр функции `createUser({ name, age, ...extraProps })`;
- `filter(({ age }) => age >= ADULT_AGE)` — достаём возраст прямо в параметре;
- `forEach(({ id, name, age }) => ...)` — при отрисовке списка;
- `const { message } = error` — достаём текст из объекта ошибки;
- `({ key }) => ...` — название нажатой клавиши в обработчике Enter.

## 6. Rest и Spread — три точки, два смысла

Одни и те же три точки `...` делают две противоположные вещи.

**Rest — «собрать остаток».** В `createUser({ name, age, ...extraProps })` после выделения `name` и `age` всё остальное собирается в объект `extraProps`. Вызов `createUser({ name: 'Anna', age: 28, city: 'Tel Aviv' })` даст `extraProps = { city: 'Tel Aviv' }`.

**Spread — «рассыпать содержимое».** В строке `{ ...extraProps, id: nextUserId(), name: cleanName, age: numericAge }` поля из `extraProps` копируются в новый объект. В `getUsers` запись `[...users]` создаёт новый массив с теми же элементами.

**Почему `id`, `name` и `age` записаны после `...extraProps`.** При одинаковых названиях побеждает свойство, записанное позже. Если бы кто-то передал свой `id`, он не должен перетереть выданный программой номер — поэтому служебные поля идут последними.

**Как не путать.** Три точки в списке параметров или слева от знака равенства собирают (rest). Три точки внутри создаваемого объекта или массива раскладывают (spread).

**Честная оговорка.** `[...users]` копирует только сам массив — объекты пользователей внутри остаются теми же. Для задания этого достаточно: внешний код не может добавить или удалить элемент во внутреннем массиве. Чтобы защитить и сами объекты, пришлось бы копировать каждый: `users.map((user) => ({ ...user }))`.

## 7. Проверка данных и ошибки

**Правила.** Имя после удаления пробелов по краям не должно быть пустым (иначе `Name is required`). Возраст не должен быть пустым (`Age is required`) и должен быть целым числом от 0 до 120 (иначе `Invalid age`).

**Ловушка с пустой строкой.** В JavaScript `Number('')` равно `0`. Если не проверить пустое поле отдельно, пустой возраст превратится в ноль и регистрация пройдёт. Поэтому пустое поле отдельно ловится дважды: в `app.js` оно становится `null`, а в `createUser` значения `null`, `undefined` и пустая строка считаются отсутствующим возрастом.

Ещё два нужных факта: `Number('abc')` даёт `NaN` («не число»), а `Number.isInteger(...)` возвращает `false` и для `NaN`, и для `25.5` — одна проверка отсекает оба случая.

**`throw new Error('текст')`** создаёт объект ошибки и немедленно останавливает функцию. Ошибка «летит» вверх по цепочке вызовов, пока кто-нибудь её не поймает.

**`try...catch...finally`** — это три части одной конструкции:

- `try` — «попробуй выполнить»: основная логика регистрации;
- `catch` — «если случилась ошибка, сделай вот это»: показать сообщение и записать его в консоль;
- `finally` — «в любом случае в конце»: вывести `Registration attempt completed`.

Зачем это нужно: ошибка внутри `createUser` не ломает всю программу. Строка `addUser` стоит после `createUser`, поэтому при ошибке до неё дело просто не доходит — некорректный пользователь в список не попадает, а ранее добавленные остаются на месте.

## 8. Замыкание — главная идея проекта

**Определение.** Замыкание — это ситуация, когда внутренняя функция «помнит» переменные из внешней функции, даже после того как внешняя функция уже закончила работу.

**Аналогия.** Мастерская изготавливает сейф с окошком выдачи и закрывается. Сейф остался у вас вместе со всем, что внутри. Положить вещь или достать её можно только через окошко (это методы), а открыть сейф напрямую нельзя.

**Как это устроено.** Обычно, когда функция завершилась, её локальные переменные исчезают. Но если внутри неё создана другая функция, которая эти переменные использует, JavaScript их не удаляет. У каждой функции есть скрытая ссылка на то «окружение», где она была создана (в спецификации она называется `[[Environment]]`). Через эту ссылку функция находит свои переменные. Пока жива внутренняя функция, живут и они.

### Пример 1. Счётчик номеров (файл `user.js`)

```js
function createIdGenerator() {
  let lastId = 0;
  return function nextId() {
    lastId += 1;
    return lastId;
  };
}
const nextUserId = createIdGenerator();
nextUserId(); // 1
nextUserId(); // 2
```

Разбор по шагам:

1. `createIdGenerator()` вызвана один раз: создала переменную `lastId = 0` и вернула внутреннюю функцию `nextId`. На этом внешняя функция закончилась.
2. `lastId` не исчезла: на неё ссылается `nextId`. Функция сохранена в `nextUserId`.
3. Каждый вызов `nextUserId()` увеличивает ту же самую `lastId` и возвращает новое значение.
4. Снаружи `lastId` не видна, поэтому счётчик нельзя случайно сбросить и получить повторяющиеся `id`.
5. Если вызвать `createIdGenerator()` ещё раз, получится второй, полностью независимый счётчик со своей `lastId`.

### Пример 2. «Журнал» пользователей (файл `userManager.js`)

```js
function createUserManager() {
  let users = [];
  return {
    addUser(user) { users.push(user); },
    getUsers() { return [...users]; },
    removeUser(userId) { /* см. файл */ },
  };
}
const userManager = createUserManager();
```

Здесь три метода — три внутренние функции, и все они ссылаются на одну и ту же переменную `users`. Снаружи её не видно: в консоли проверка `typeof users` даёт `undefined` (при проверке проекта это подтвердилось). Именно так выполнены требования задания: массив не глобальный и из `app.js` напрямую недоступен.

**Почему не обычный глобальный массив.** Любая строка кода могла бы случайно написать `users = []` и стереть всех или добавить в массив мусор. Замыкание создаёт «капсулу» (это называется инкапсуляцией): состояние защищено, и менять его можно только теми способами, которые предусмотрел автор.

**Почему `getUsers` отдаёт копию.** Если бы метод возвращал сам массив, внешний код получил бы ключ от сейфа и мог бы вызвать `push` или `splice` в обход `addUser` и `removeUser`. Копия `[...users]` — это распечатка журнала: её можно резать и портить, оригинал не пострадает. Так же работает фильтр Show Adults: он создаёт новый массив и не трогает журнал.

### Пример 3. Кнопка Delete (файл `app.js`)

```js
visibleUsers.forEach(({ id, name, age }) => {
  // ...создаём строку и кнопку...
  deleteButton.addEventListener('click', () => handleDelete(id, name));
});
```

На каждом проходе цикла создаётся своя маленькая функция, которая помнит свои `id` и `name`. Поэтому нажатие Delete у Anna удалит именно Anna. Нажатие может произойти через минуты, когда цикл давно закончился, но значения сохранены — снова благодаря замыканию.

### Частые ошибки

- Думать, что внутренняя функция получает копию значения. На самом деле она держит ссылку на саму переменную — поэтому `lastId` растёт от вызова к вызову.
- Вернуть из фабрики сам массив. Тогда капсула разрушена, и инкапсуляция потеряна.
- Вызвать `createUserManager()` дважды. Получатся два независимых журнала с разными пользователями.

**Одной фразой для защиты работы:** замыкание — это функция вместе с теми переменными, среди которых она родилась. Мы использовали его, чтобы хранить состояние приложения в закрытом месте и выдавать наружу только безопасные операции.

## 9. Методы и команды: что делает каждая и почему выбрана

### Методы «журнала» (`userManager.js`)

| Метод | Что делает | Почему так |
| --- | --- | --- |
| `addUser(user)` | Кладёт готового пользователя в конец внутреннего массива командой `push`. | Метод не знает о странице (не трогает DOM). Поэтому «журнал» можно использовать в любом проекте, а за вывод на экран отвечает только `app.js`. |
| `getUsers()` | Возвращает новый массив `[...users]`. | Оригинал защищён от внешних изменений (раздел 8). |
| `removeUser(userId)` | Оставляет в массиве всех, у кого `id` не равен удаляемому, и возвращает `true`, если пользователей стало меньше, иначе `false`. | Это расширение для доп. задания B. Так как `filter` создаёт новый массив, переменная `users` объявлена через `let` и получает это новое значение. Возврат `true` или `false` позволяет `app.js` понять, получилось ли удаление. |

### Работа со строками и числами

| Команда | Что делает | Где и зачем |
| --- | --- | --- |
| `trim()` | Убирает пробелы в начале и в конце строки: `'  Sarah  '` становится `'Sarah'`. | Очистка имени; проверка, что имя не состоит из одних пробелов. |
| `Number(x)` | Превращает значение в число: `'28'` → `28`, `'abc'` → `NaN`, `''` → `0`. | Возраст из поля ввода приходит как текст, а нужно число. |
| `Number.isInteger(x)` | Даёт `true`, только если `x` — целое число. | Одной проверкой отсекает дробные значения и `NaN`. |
| `String(x)` | Превращает значение в строку. | Проверка пустоты возраста; запись числа в `textContent` и в атрибут `aria-pressed`. |

### Работа с массивами

| Команда | Что делает | Где и зачем |
| --- | --- | --- |
| `push(item)` | Добавляет элемент в конец массива, меняя сам массив. | `addUser`. |
| `filter(fn)` | Создаёт новый массив из тех элементов, для которых `fn` вернула `true`; исходный массив не меняет. | `removeUser` (удаление) и фильтр Show Adults (возраст от 18). |
| `forEach(fn)` | Вызывает `fn` для каждого элемента. Ничего не возвращает. | Построение строк списка; подключение клавиши Enter к двум полям. |

### Работа со страницей (DOM)

DOM — это «живая модель» страницы в памяти браузера. Меняя её, мы меняем то, что видит человек.

| Команда | Что делает | Где и зачем |
| --- | --- | --- |
| `document.querySelector('#id')` | Находит на странице первый элемент по CSS-селектору. | Поиск полей, кнопок, списка. Выполняем один раз и сохраняем результат в константы. |
| `document.createElement('li')` | Создаёт новый элемент, который пока не виден. | Строки списка, кнопки Delete. |
| `textContent` | Записывает в элемент обычный текст. | Имя и возраст, сообщения. Безопасность — в разделе 10. |
| `append(...)` | Вставляет элементы внутрь другого элемента (можно несколько сразу). | Сборка строки: имя, возраст, кнопка. |
| `replaceChildren()` | Без аргументов удаляет всё содержимое элемента. | Очистка списка перед новой отрисовкой, чтобы пользователи не дублировались. |
| `classList.add / remove / toggle` | Добавляет и убирает CSS-классы. `toggle(имя, true или false)` включает или выключает класс. | Цвет сообщения (ошибка или успех); подсветка активного фильтра. |
| `setAttribute(имя, значение)` | Записывает HTML-атрибут. | Подписи `aria-label` и состояние `aria-pressed` для программ экранного чтения. |
| `addEventListener('click', fn)` | Подписывает функцию на событие. | Кнопки Register, Delete, Show All, Show Adults; клавиша Enter. |
| `focus()` | Ставит курсор в поле. | После регистрации курсор возвращается в поле имени. |

### Консоль браузера

Консоль открывается клавишей F12 (вкладка Console).

- `console.log(...)` — обычное сообщение: что происходит в программе.
- `console.error(...)` — сообщение об ошибке (красным).
- `console.warn(...)` — предупреждение (жёлтым).

## 10. Безопасность: почему `textContent`, а не `innerHTML`

Человек может ввести в поле имени что угодно, например `<img src=x onerror=alert(1)>`. Если записать такой текст в страницу через `innerHTML`, браузер примет его за разметку и выполнит чужой код. Это называется XSS-атакой, и это одна из самых частых уязвимостей сайтов. Команда `textContent` всегда вставляет строку как обычный текст, никогда как разметку. Поэтому задание запрещает `innerHTML` для пользовательских данных. При проверке проекта такое имя отобразилось на странице буквально, как текст, и ни один лишний элемент не появился.

## 11. Дополнительные задания A, B, C

**A. Счётчик пользователей.** В заголовке списка стоит `Total: N`. Число лежит в элементе `#user-count`, и функция `renderUsers` записывает туда `allUsers.length`. Поскольку `renderUsers` вызывается после каждой регистрации, удаления и смены фильтра, число всегда актуально. Счётчик показывает общее количество зарегистрированных, а не количество строк на экране.

**B. Удаление.** В «журнал» добавлен метод `removeUser(id)` (раздел 9). Рядом с каждым пользователем выводится кнопка Delete. Её обработчик — замыкание из примера 3: он помнит `id` своей строки и вызывает `handleDelete`. Если удаление удалось, список и счётчик перерисовываются.

**C. Фильтрация.** Две кнопки, Show All и Show Adults, переключают значение `currentFilter` (`'all'` или `'adults'`). Функция `getVisibleUsers` для `'adults'` вызывает `filter(({ age }) => age >= 18)`. Так как `filter` и `getUsers` создают новые массивы, внутренний массив журнала при переключении не меняется. Если включён Show Adults и зарегистрирован человек младше 18, счётчик вырастет, а в списке он не появится: он в журнале, но фильтр его скрывает. Это не ошибка, так задумано.

## 12. Оформление: концепция «Спокойный деловой стиль»

Цель оформления — строгий, аккуратный вид, который не утомляет глаза при длительной работе и проверке. Для этого выбраны холодные светлые тона, мягкий контраст и один спокойный акцентный цвет.

| Роль | Цвет | Назначение |
| --- | --- | --- |
| Фон страницы | `#edf1f2` | светлый туманно-серый, без резкой белизны |
| Поверхность | `#ffffff` | панель формы и поля ввода |
| Текст | `#1e2a30` | тёмный сланцево-синий, мягче чистого чёрного |
| Акцент | `#2d6a66` | еловый сине-зелёный: кнопка, активный фильтр, полоса сверху |
| Ошибка | `#9c3b33` на `#fbecea` | приглушённый кирпичный: заметен, но не кричит |
| Подтверждение | `#2f6b4b` на `#e7f2eb` | спокойный зелёный |

**Принципы.**

- **Один акцент.** Яркий цвет есть только у главных действий — так взгляд сразу находит кнопку Register.
- **Шрифты.** Заголовки набраны Georgia (строгие засечки), интерфейс — системным шрифтом без засечек. Оба есть на компьютере, ничего не скачивается из интернета, поэтому проект запускается без подключения к сети.
- **Ошибка отличается от обычного текста** цветом, фоном и полосой слева, а не только цветом: так её заметят и люди с особенностями цветового зрения.
- **Пустой список** не оставляет человека в тупике: он объясняет, что делать дальше.
- **Доступность:** у полей есть невидимые для глаза подписи для программ экранного чтения, при работе с клавиатурой виден контур выбранного элемента, а при системной настройке «уменьшить анимацию» плавные переходы отключаются.
- **Адаптивность:** на экранах уже 480 пикселей поля занимают всю ширину, кнопки фильтров делят строку поровну, заголовок списка переносится в два ряда.

Цвета и размеры вынесены в переменные в начале `main.css`. Чтобы изменить всю гамму, достаточно поправить несколько строк.

## 14. Глоссарий

| Термин | Простыми словами |
| --- | --- |
| Аргумент | значение, которое передают функции при вызове |
| Деструктуризация | «распаковка» объекта в отдельные переменные |
| DOM | живая модель страницы, которой управляет JavaScript |
| Замыкание | функция, которая помнит переменные места, где была создана |
| Инкапсуляция | защита данных: менять их можно только разрешёнными способами |
| Исключение, ошибка | сигнал «что-то пошло не так», прерывающий выполнение |
| Обработчик события | функция, которая запускается при нажатии, вводе и т. п. |
| Rest | три точки, которые собирают остальное в один объект или массив |
| Spread | три точки, которые раскладывают объект или массив на части |
| Фабрика функций | функция, которая создаёт и возвращает другие функции или объекты |
| `defer` | атрибут скрипта: выполнить после разбора страницы и по порядку |
| `id` | уникальный номер пользователя |
